# Phase 0: YC六问战略评估

> **门控**: G0 (Strategy Gate) — 至少4个问题有满意回答 → 通过
> **Layer**: Layer 1 → Layer 3
> **适用模式**: Standard（条件跳过）, Strict（必跑）
> **前置产物**: `00-strategy.md`

---

## 📋 YC六问清单

1. **痛点有多痛？** 用户在解决什么问题？不解决的代价是什么？
2. **现有方案有哪些？** 为什么它们不够好？
3. **你的独特优势是什么？** 为什么是你能做、别人做不了？
4. **怎么获客？** 用户从哪里来？获客成本多少？
5. **怎么赚钱？** 商业模式是什么？LTV/CAC比多少？
6. **2倍速验证** 如果明天资源翻倍，做什么能最快拿到结果？

## ⚡ v3.2 交互流程

### 第1步：批量展示所有问题（不提问）

```

以下是需要评估的6个战略问题，回答进度：

[1/6] ● 痛点有多痛？
[2/6] ○ 现有方案有哪些？
[3/6] ○ 你的独特优势是什么？
[4/6] ○ 怎么获客？
[5/6] ○ 怎么赚钱？
[6/6] ○ 2倍速验证？

─────────────────────────────

现在逐个回答（每题有预设选项，选字母或输入自定义内容）：
```

### 第2步：逐个提问，每题提供预设选项

```
问题 1/6：痛点有多痛？

用户在解决什么问题？不解决的代价是什么？

请选择最接近的答案：

  [A] 很痛 — 用户每天被这个问题困扰，不解决会直接影响收入/效率
  [B] 较痛 — 是现有流程中的痛点，但有 workaround 能凑合
  [C] 一般 — 不是最核心的问题，但解决了会更好
  [D] 不太痛 — 锦上添花的功能

  或输入自定义内容（直接打字，发送后进入下一题）：
```

### 第3步：用户回答后更新进度，继续下一题

```
✅ [1/6] ● 痛点有多痛？→ 用户选 A

[2/6] ● 现有方案有哪些？
[3/6] ○ 你的独特优势是什么？
[4/6] ○ 怎么获客？
[5/6] ○ 怎么赚钱？
[6/6] ○ 2倍速验证？

─────────────────────────────

问题 2/6：现有方案有哪些？

为什么它们不够好？

  [A] 没有现成方案 — 这是个全新的需求/市场
  [B] 有 1-2 个竞品 — 但体验/价格/功能有明显差距
  [C] 有多款成熟竞品 — 但都不够本地化/不够便宜/太重
  [D] 用 Excel/手写/人工 — 完全靠手工流程

  或输入自定义内容（直接打字，发送后进入下一题）：
```

### 第4步：6题全部回答完毕后触发 G0 门控

```
✅ Phase 0 完成 — YC六问全部回答完毕

回答汇总：
1. 痛点：A — 很痛，直接影响收入/效率
2. 现有方案：C — 有多款成熟竞品但不够本地化
3. 独特优势：...
4. 获客：...
5. 赚钱：...
6. 2倍速：...

G0 门控：6/6 已回答 ✅ 通过 → 进入 Phase 1

请确认或输入 /skip 跳过 Phase 0（仅 Standard 模式可条件跳过）：
```

**⚠️ stop-on-G1**: G1未通过（问题<4个有满意回答）→ 退回需求澄清，不进入 Phase 2。

## ⚠️ Phase 0 条件跳过规则（Standard 模式）

满足任意 **2项即可跳过**：

- ✅ brownfield 项目（已有代码库）
- ✅ 用户需求描述具体明确（非"做个APP"类模糊表述）
- ✅ 任务是优化/修复/小功能，非新项目/新方向
- ✅ 项目已有完整上下文（MEMORY.md/CLAUDE.md/CONTEXT.md）
- ❌ 用户说"我想做一个XX"类从零开始的表述 → 必跑

**跳过时的替代动作**：直接用用户需求描述生成简版 `00-strategy.md`（1段话：背景+目标+范围）。
