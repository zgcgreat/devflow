## Phase 2: DAG路由决策 + Provider智能路由

### DAG路由决策

根据需求复杂度自动判定：

| 复杂度 | Wave数量 | 并行度 | 示例 |
|--------|---------|--------|------|
| 简单 | 1 Wave | 无依赖串行 | Bug修复、文案调整 |
| 中等 | 2-3 Waves | 波内并行 | CRUD功能、页面开发 |
| 复杂 | 4+ Waves | 波间依赖 + 波内并行 | 微服务拆分、架构重构 |

### Provider智能路由

根据任务类型选择模型：

| Phase | 任务类型 | 推荐Provider/Model特性 |
|-------|---------|----------------------|
| Phase 0-1 | 理解+分析 | 高检索能力模型 |
| Phase 2-2a | 创意设计 | 高创造力模型 |
| Phase 3 | 逻辑编排 | 强推理模型 |
| Phase 4 | 代码生成 | 高代码能力模型 |
| Phase 5 | 测试编写 | 细心严谨型模型 |
| Phase 6 | 对抗审查 | 高分析+批判型模型 |
| Phase 7-8 | 集成归档 | 标准模型即可 |

## Phase 2a: 设计枪战 (v3新增)

> **门控**: G3.5 (Variant Selection Gate) — 用户确认设计方案 → 通过
> **触发条件**: 前端/UI项目、task涉及UI文件时必跑；其他项目AI推荐。

### ⚡ v3.2 交互流程

**第1步：展示设计变体对比表**

```
=== Phase 2a: 设计方案选择 ===

已生成 4 个设计方案，请对比后选择：

┌──────┬──────────┬──────────┬──────────┬──────────┐
│ 方案 │ 风格     │ 优点     │ 风险     │ 推荐度   │
├──────┼──────────┼──────────┼──────────┼──────────┤
│ A    │ 极简风   │ 简洁    │ 信息密度 │ ⭐⭐⭐⭐  │
│      │          │ 开发快   │ 低       │ (推荐)   │
├──────┼──────────┼──────────┼──────────┼──────────┤
│ B    │ 卡片式   │ 结构化好 │ 需要更多 │ ⭐⭐⭐⭐   │
│      │          │ 适合内容 │ 空间     │          │
├──────┼──────────┼──────────┼──────────┼──────────┤
│ C    │ 表格为主 │ 数据密集 │ 交互复杂 │ ⭐⭐⭐    │
│      │          │ 适合后台 │ 开发慢   │          │
├──────┼──────────┼──────────┼──────────┼──────────┤
│ D    │ 混合模式 │ 灵活     │ 一致性差 │ ⭐⭐⭐    │
│      │          │ 兼顾两者 │ 维护难   │          │
└──────┴──────────┴──────────┴──────────┴──────────┘

AI 推荐：方案 A — 极简风（开发快，适合 MVP）
```

**第2步：用户选择或自定义**

```
请选择方案：

  [A] 方案 A — 极简风（推荐）
  [B] 方案 B — 卡片式
  [C] 方案 C — 表格为主
  [D] 方案 D — 混合模式
  [E] 组合方案（描述你需要的组合）
  [F] 重新生成（不满意当前选项）

  或输入自定义方案：
```

**第3步：用户选择后生成最终设计方案**

```
✅ Phase 2a 完成 — 选择了方案 A

最终设计方案：
- 风格：极简风
- 核心：减少视觉噪音，突出核心数据
- 布局：左侧导航 + 顶部搜索 + 主内容区
- 技术选型：Ant Design Pro Layout

已更新：`.forgeos/<req-id>/02-design.md`

请确认或输入 [E] 选择其他方案：
```

**防决策疲劳**: AI推荐必须有明确依据，不列一堆让用户自己猜。
