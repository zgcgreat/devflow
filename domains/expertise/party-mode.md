# ForgeOS · Party Mode 仲裁器

> 一个房间里放 3-6 个专家，让他们吵出最佳方案。

## ⚡ 激活条件

| 场景 | 必选角色 | Party 人数 |
|------|---------|-----------|
| 架构变更 | 架构师 + 开发者 + QA | 3 |
| API 设计 | 开发者 + 安全官 + 架构师 | 3 |
| 安全方案 | 安全官 + 开发者 + 架构师 | 3 |
| 前端/UI | 设计师 + 开发者 + PM | 3 |
| 复杂需求 | CEO + 架构师 + 开发者 + PM + QA + 安全官 | 6 |
| 发布决策 | CEO + 发布工程师 + QA | 3 |

## 🎯 仲裁协议

```
Step 1: 仲裁器 加载任务描述 + 领域上下文
Step 2: 仲裁器 选择 3-6 个角色（按上表）
Step 3: 每个角色独立输出方案：
        格式: 「角色名: 方案摘要 + 理由 + 风险 + 预估成本」
Step 4: 仲裁器 收集 → 生成对比表（文本表格）：

| 方案 | 角色 | 成本 | 性能 | 可维护 | 安全 | 总分 |
|------|------|------|------|--------|------|------|
| A    | 架构师 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ | 2.75 |
| B    | 开发者 | ⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | 2.75 |
| C    | 安全官 | ⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ | 2.75 |

Step 5: 仲裁器 按加权总分推荐最优路径
Step 6: 用户选择 → 继续执行
```

## 📋 强制规则

1. **平行输出** — 所有角色同时输出，不等待顺序
2. **角色不可串** — 开发者不能说出架构师的专业观点
3. **允许反驳** — 在对方方案上标注"异议" + 理由
4. **仲裁中立** — 仲裁器不参与方案设计，只做对比评分
5. **评分透明** — 加权维度（成本 0.25 / 性能 0.25 / 可维护 0.3 / 安全 0.2）
6. **输出产物** → 写入 `02a-variants.md`（规格域模板）

## 🔄 调用方式

**从 execution 域激活（Phase 2a）**：
```
用户: 设计登录方案
→ 内核路由到: domains/execution/_SKILL.md → Phase 2a
→ Phase 2a 加载: domains/expertise/_SKILL.md → Party Mode
→ 选择: [架构师, 开发者, 安全官]
→ ... 3 个方案 → 对比表 → 仲裁 ...
```

**直接从 `@party` 命令激活**：
```
@party "设计一个数据库迁移策略"
→ 加载: expertise/_SKILL.md → Party Mode
→ ... 同上协议
```
