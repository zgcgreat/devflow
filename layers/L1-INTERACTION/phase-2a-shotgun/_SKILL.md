## 输入

- `02a-design-variants.md` — N个设计变体 + AI推荐最优项

## ⭐ 核心创新: 防决策疲劳设计枪战

Phase 2a 自动生成 4-6 个设计方案变体，每个标注优缺点和风险评估，AI 推荐最优选项并说明理由。

**关键原则**: AI推荐必须有明确依据（可维护性、用户习惯、开发成本三维度评分），不列一堆让用户自己猜。

## 执行流程

### Step 1: 变体规划

基于 Phase 2 方案，确定变体生成维度：
- **布局维度**: 左侧导航 / 顶部导航 / 侧边栏抽屉 / 全屏模态框
- **交互维度**: 渐进披露 / 一次性展示 / 标签页切换
- **视觉复杂度**: 极简(纯功能) / 标准(适度装饰) / 丰富(动效+微交互)

### Step 2: 生成变体 (并行/串行迭代)

**⚠️ 强制规则**: 至少4个变体，每个变体必须包含：
- 核心设计理念（1句话概括）
- 优点列表（3+条）
- 风险/成本评估（1-2条）
- 适用场景说明
- 可维护性评分(1-5)

```markdown
# Phase 2a: 设计枪战 — [需求简述]

## 变体 #1: 渐进披露卡片式 (推荐 ⭐)

**设计理念**: "用户只需关注当前步骤，减少认知负荷"

优点:
- 移动端友好，单步聚焦
- 开发成本最低（纯组件复用）
- 易于扩展新步骤

风险:
- 多步骤操作效率略低

适用: B端工具类应用，高频重复操作场景

可维护性: 4/5

## 变体 #2: 标签页切换式

**设计理念**: "所有信息平铺展示，用户自由跳转"

优点:
- 快速对比不同部分
- 支持任意顺序填写

风险:
- 移动端需横向滚动
- 状态同步复杂度中等

适用: C端表单类应用，单次填写<5分钟场景

可维护性: 3/5

... (变体 #3, #4, #5...)
```

### Step 3: AI 推荐最优项

**⚠️ 强制规则**: 必须有评分和选择理由。

```markdown
## AI 推荐: 变体 #1 (渐进披露卡片式)

| 维度 | #1渐进 | #2标签 | #3全屏模态 | #4分步Wizard |
|------|--------|--------|-----------|-------------|
| 可维护性 | 4/5 ⭐ | 3/5 | 2/5 | 3/5 |
| 开发成本 | 低 | 中 | 高 | 中 |
| 用户体验 | 好 | 好 | 一般(遮挡) | 好 |
| 扩展性 | 优 | 良 | 差 | 良 |

**推荐理由**: 
1. 维护性最高(4/5)，后续迭代成本最低
2. 开发成本最低，优先实现核心功能
3. 与现有组件库的渐进披露模式一致

**建议组合**: 以#1为基础，借鉴#2的标签切换用于"高级设置"子页面。
```

### Step 4: 用户选择/组合

```markdown
请选择:
1. ✅ 采用推荐方案 (变体 #1)
2. 选择自定义变体: #_
3. 组合多个变体的特性: (描述组合方式)
4. AI重新生成 (提供新的设计约束)
```

### Step 5: 输出最终设计方案

用户确认后，整合为 `02a-design-final.md`。
