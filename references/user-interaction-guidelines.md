# 用户交互规范

> **适用范围**：所有 devflow-kit stage 的用户确认环节
> **参考来源**：`references/prompts/0-confirm.md`
> **版本**: v3.2 — 选择题交互模式

## 核心原则

1. **批量展示 + 逐个选择题** ⭐v3.2：先展示全局进度，然后逐个提问，每题提供预设选项（A/B/C/D），用户只需用键盘选择
2. **默认明确**：标明推荐选项（✅ 推荐）
3. **自定义回退**：当预设选项不覆盖用户需求时，提供 [D] 其他（自定义输入）
4. **进度可视化** ⭐v3.2：每个阶段结束前输出进度面板（已完成/进行中/未开始）

---

## 一、单问题确认格式

### ✅ 正确示例

```markdown
---
**请选择下一步：**

[1] ✅ 确认，继续下一阶段 ← 推荐
[2] 查看产物详情
[3] 需要修改

请回复 1/2/3。
```

### ❌ 错误示例

```markdown
请确认产物内容是否正确：
- ✅ 确认，继续下一阶段
- ❌ 需要修改：`<具体修改内容>`
```

**问题**：用户需要输入完整文字，增加认知负担。

---

## 二、多问题确认格式（参考 0-confirm 步骤 5）

### 原则 ⭐v3.2

> **逐个提问，每题一个选择题**。先批量展示所有问题概览，然后逐个提问，等用户回答再继续。

### Step 1: 批量展示问题概览（⭐v3.2 新增）

```markdown
## 📋 全局进度

[1/3] ● 问题 1 ← 当前提问
[2/3] ○ 问题 2
[3/3] ○ 问题 3

---
**问题 1**：<问题描述>
[A] <选项A> ← 推荐
[B] <选项B>
[C] <选项C>
[D] 其他（自定义输入）

请回复选项字母（如 "A"）。
```

### Step 2: 逐个提问（⭐v3.2 核心）

**每次只问一个问题**，提供 3~4 个预设选项：

```markdown
📍 当前阶段：<stage-name> · <阶段描述>
🎯 本步目标：<本次确认的目标>

---
**问题 N/M**：<问题描述>
[A] <选项A> ← 推荐
[B] <选项B>
[C] <选项C>
[D] 其他（自定义输入）

请回复选项字母（如 "A"）。
```

### Step 3: 用户回答后更新进度 + 下一题（⭐v3.2）

```markdown
✅ [1/M] ● 问题 1 → 选 A
[2/M] ● 问题 2（当前）
[3/M] ○ 问题 3

---
**问题 2/M**：<问题描述>
[A] <选项A> ← 推荐
[B] <选项B>
[C] <选项C>
[D] 其他（自定义输入）

请回复选项字母。
```

## 三、阶段完成确认格式（参考 0-confirm 阶段完成声明）

### 产物确认

```markdown
✅ <阶段名称> 完成
📝 产物：.devflow/<req-id>/<产物文件>
📊 STATE.md 阶段进度已更新：[x] <阶段> → <产物>

请确认产物内容：
- <关键点1>: <值>
- <关键点2>: <值>
- <关键点3>: <值>

---
**请选择下一步：**

[1] ✅ 确认，继续下一阶段 ← 推荐
[2] 查看产物详情
[3] 需要修改

请回复 1/2/3。
```

### 发布确认

```markdown
---
## 🚀 准备发布

### 发布内容
- 版本：vX.X.X
- 新增功能：...

### 发布检查
- [x] 测试通过
- [x] Code Review 通过
- [x] 文档已更新

---
**请选择：**

[1] ✅ 确认发布 ← 推荐
[2] 推迟发布

请回复 1/2。
```

## 四、架构级变更检测（参考 0-confirm 步骤 2）

### 命中后停下来反问

```markdown
🏛️ 检测到本次描述涉及**项目级架构变更**：
   - 命中信号：<具体信号>

这种规模建议先跑架构梳理：

---
**请选择：**

[1] ✅ 先跑架构梳理（推荐）
[2] ⚠️ 我清楚影响，继续当前流程
[3] ↩️ 这其实是需求级局部改造（请说明理由）

请回复 1/2/3。无确认前不进后续步骤。
```

## 五、视觉调性选择（参考 0-confirm 步骤 4）

### 红线：本步不出其他问题

```markdown
📍 项目：<项目名>
🎯 一句话：<业务描述>

### 视觉调性选项

[1] <调性1> - <关键词> ← 推荐（理由）
[2] <调性2> - <关键词>
...
[9] <调性9> - <关键词>

❌ 不推荐：<调性X>（理由）、<调性Y>（理由）

请回复数字（如 "6"）或描述你想要的感觉，选定后我再问其他问题。
```

## 六、特殊情况处理

### 用户选择"需要修改"

```markdown
📝 请说明需要修改的内容：

直接输入修改意见，例如：
- "任务3的时间预估需要调整"
- "设计文档缺少数据库设计"
```

用户输入后：
```markdown
✅ 已记录修改意见：<用户输入>

正在重新生成...
```

### 用户选择"查看产物详情"

```markdown
---
**产物详情：**

### <产物名称>

<产物内容摘要或全文>

---
**请选择下一步：**

[1] ✅ 确认，继续 ← 推荐
[2] 需要修改

请回复 1/2。
```

## 七、选项编号规则

| 编号 | 含义 | 标记 |
|---|------|---|
| 1 | 推荐选项 | `✅ ... ← 推荐` |
| 2 | 备选选项 | `⚠️ ...` |
| 3 | 查看详情 | `查看产物详情` |
| 4 | 需要修改 | `需要修改` |
| 5+ | 其他选项 | 根据具体情况添加 |

**标记规则**：
- 推荐选项：`✅ ... ← 推荐`
- 警告选项：`⚠️ ...`
- 用户可直接输入数字或选项文字
